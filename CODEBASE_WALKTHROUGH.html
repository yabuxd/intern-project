1. Executive Overview & Tech Stack Matrix

This codebase implements a full-stack, enterprise-grade restaurant management and point-of-sale system. It integrates public customer ordering (dine-in with table selection and home delivery with live dispatch), staff table reservations with automated timeslot conflict checking, expediter and kitchen queues, driver assignment, cashier payment verification (Cash and Chapa ETB online gateway), staff menu modification proposals, and administrative role-based access control (RBAC).

Layer Technology / Framework Architectural Purpose
Frontend SPA React 19, TypeScript, Vite 8, Tailwind CSS v4, TanStack Query v5 Client-side rendered application with late-night bistro aesthetic, micro-animations, and responsive layouts.
Backend REST API Laravel 12/13, PHP 8.3+, Eloquent ORM, Firebase JWT RESTful API enforcing business rules, authorization Gates, transaction boundaries, and rate limits.
Identity & Auth Supabase Auth (ES256 JWKS asymmetric keys) Decoupled auth provider issuing cryptographically signed JWTs validated locally on Laravel.
Live Synchronization Supabase Realtime (WebSocket) + 5s Polling Fallback Live order updates for kitchen queues and dispatchers with automated degradation resilience.
Database Layer Supabase PostgreSQL (Production) / SQLite (Dev & Tests) Relational schema with composite indexes, foreign key constraints, and RLS security policies.
Payment Gateway Chapa API (Ethiopian Birr / ETB) + Cash Desk Dual payment handling: instant online checkout verification + cashier desk approval gate.
Shared Contracts @intern/shared (TypeScript npm workspace) Shared type definitions, DTO envelopes, enums, roles, and permission constants.

3. System Entry Points & Lifecycle Bootstrapping

Client Bootstrap (React 19)

  1. client/index.html mounts font stylesheets and #root DOM container.
  2. main.tsx initializes React in StrictMode and provides the global QueryClientProvider.
  3. App.tsx encapsulates navigation with BrowserRouter and mounts AuthProvider.
  4. AuthContext.tsx triggers supabase.auth.getSession(), listens to onAuthStateChange, and queries GET /api/me to populate user permissions.
  5. Protected routes are gated via ProtectedRoute checking session and permission tokens.

Server Bootstrap (Laravel 12/13)

  1. server/public/index.php receives HTTP requests and invokes the Laravel kernel.
  2. bootstrap/app.php registers routing, configures global SecurityHeaders middleware, and sets JSON exception formatting for api/*.
  3. AppServiceProvider.php registers singletons (ApiCacheService, SupabaseJwtService), defines rate limits, and dynamically registers Gates from Permission::catalog().
  4. routes/api.php processes endpoints through throttle:api and VerifySupabaseJwt.

Key Database Entities

  • User: Uses UUID primary keys mapped directly to Supabase Auth sub. Maintains a many-to-many relationship with Role. Auth profiles and effective permissions are cached in-memory and in cache store via ApiCacheService.
  • Order: Holds fulfillment type (dine_in, delivery), table reference, delivery coordinates/phone/notes, assigned driver, payment method (cash, chapa), payment status, and dual cashier validation timestamps.
  • OrderItem: Normalized line items capturing immutable snapshots of unit prices and computed line totals.
  • RestaurantTable: Physical restaurant table records containing seat capacities and operational statuses (free, reserved, occupied).
  • Reservation: Table bookings capturing party_size, start/end timestamps, and reservation status (confirmed, cancelled).
  • MenuCategory & MenuItem: Menu taxonomy with sort ordering, prices in ETB, availability flags, and image storage paths.
  • MenuChangeRequest: Moderation queue for staff proposals (creation or deletion of menu items) awaiting manager approval.
  • StaffNotification: In-app operational notification queue alerting cashiers and managers to pending actions.

6. Deep-Dive Business Logic & Workflows

Workflow 1: Dual-Fulfillment Order State Machine

Orders follow strict state progression modeled in Order.php and enforced in OrderController::updateStatus. Dine-in and Delivery paths branch dynamically with distinct permission gates.

Critical Dispatch Invariant
An order cannot transition to out_for_delivery unless a valid driver_id is assigned. Only the assigned driver or users with can_manage_deliveries can mark an order delivered.

Workflow 2: Hybrid Payment Settlement & Cashier Approval Gate

To prevent unpaid orders from consuming kitchen resources while supporting immediate cash seating, the kitchen queue enforces the scopePaymentSettled database scope: 

// App\Models\Order::scopePaymentSettled
public function scopePaymentSettled($query)
{
    return $query->where(function ($builder) {
        $builder
            ->where('payment_status', self::PAYMENT_NOT_REQUIRED) // Cash orders
            ->orWhere(function ($chapa) {
                $chapa
                    ->where('payment_status', self::PAYMENT_PAID)    // Online Chapa paid
                    ->whereNotNull('cashier_approved_at');            // AND approved by cashier!
            });
    });
}

Workflow 3: Supabase JWT Verification & JIT User Synchronization

  1. Authorization Header Extraction: Extracts bearer token from Authorization: Bearer <token>.
  2. Algorithm Header Inspection: Determines algorithm (ES256 vs legacy/test HS256).
  3. JWKS Verification: For ES256, fetches and caches Supabase JWKS from /.well-known/jwks.json for 24 hours. Validates cryptographic signature using firebase/php-jwt. Falls back to /auth/v1/user API on connection issues.
  4. Claims Cache: Caches valid JWT claims for 90 seconds (auth.jwt.<hash>) to avoid redundant cryptographic decoding.
  5. JIT Local Synchronization: Upserts the user record into the local users table matching id = claims.sub. New sign-ups are automatically granted the customer role.
  6. User Context Injection: Attaches resolved User instance to Auth::setUser($user) and $request->setUserResolver().

Workflow 4: Table Reservation & Conflict Prevention Engine

Managed by ReservationController and ReservationAvailabilityService using row-level locking:

  1. Executes inside a database transaction with RestaurantTable::lockForUpdate().
  2. Validates that party_size <= table.capacity.
  3. Asserts that no conflicting reservation exists within the requested window: starts_at < $endsAt AND ends_at > $startsAt AND status = 'confirmed'.
  4. Creates the confirmed reservation and flushes the admin dashboard analytics cache.

8. Cross-Cutting Concerns & Security Architecture

Two-Tier Caching Architecture (ApiCacheService.php)

  • Tier 1: Request-Lifecycle Static RAM Cache (0ms): Process-level memory array private static array $memoryCache caching entities and permission resolutions within the same request lifecycle.
  • Tier 2: Persistent Cache Store: Caches menu payloads (api.menu.public.v2), tables catalog, roles catalog, driver lists, and computed admin dashboards with sha256 date-range keys.
  • HTTP ETag Negotiation: /api/menu and /api/tables compute md5 payload hashes and return 304 Not Modified when matched against If-None-Match headers.

Keyset (Cursor) Pagination (KeysetPaginator.php)

Replaces standard SQL OFFSET / LIMIT with WHERE id > :after_id LIMIT n + 1. This prevents full-table scan degradation on high-volume order and reservation tables.

Rate Limiting & Security Headers

  • Rate Limiters: api (120/min per user/IP), orders (30/min), uploads (15/min), payments (60/min per IP).
  • Security Headers: Injected on all responses: X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, X-XSS-Protection: 1; mode=block, Referrer-Policy: strict-origin-when-cross-origin.

10. Local Installation, Build & Testing Manual

Prerequisites

  • Node.js 20+ and npm 10+
  • PHP 8.3+ with extensions: openssl, curl, mbstring, pdo_sqlite, pdo_pgsql, fileinfo
  • Composer 2+

Step-by-Step Execution

# 1. Install dependencies across all monorepo packages
npm install
cd server && composer install && cd ..

# 2. Configure environment variables
cp .env.example .env
cp client/.env.example client/.env
cp server/.env.example server/.env

# 3. Migrate and seed the database
cd server
php artisan migrate --seed
cd ..

# 4. Start the development servers in two terminals:
# Terminal 1: Laravel API Backend (:8000)

npm run dev

npm run build                       # Build TypeScript shared contracts and client SPA
npm run lint                        # Lint shared and client packages

11. Architectural Observations, Risks & Mitigations

Area Architectural Observation / Gotcha Implemented Mitigation
JWKS Network Overhead Validating ES256 tokens against remote Supabase JWKS could introduce network latency if fetched per request. SupabaseJwtService caches JWKS for 24 hours (86400s) and caches decoded JWT claims in Redis/File cache for 90 seconds.
Windows PHP SSL Certificates PHP on Windows environments may fail HTTPS requests to Supabase or Chapa if curl.cainfo is omitted. SupabaseJwtService::resolveCaBundle automatically checks services.supabase.ssl_cert_file, curl.cainfo, and openssl.cafile paths.
Chapa Webhook in Local Dev Chapa requires a public HTTPS URL for asynchronous webhook notifications. ChapaPaymentService detects localhost origins, avoids dispatching local webhook URLs, and relies on client return verification (/orders/{id}/payment/verify).
PostgreSQL vs SQLite DDL PostgreSQL-specific RLS policies (ALTER TABLE ... ENABLE ROW LEVEL SECURITY) fail on SQLite in local tests. Migration 2026_08_14_180100_add_supabase_rls_policies.php checks DB::getDriverName() === 'pgsql' prior to executing PostgreSQL DDL.
Realtime Channel Fallback Local SQLite does not publish PostgreSQL replication change feeds to Supabase Realtime. useOrdersRealtime.ts detects unestablished Realtime connections within 2.5s and automatically switches to 5-second polling.
